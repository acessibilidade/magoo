COMPONENT GUIDE

Explore behaviors before defining the interface.

Quick guide for designers

Always consider the context of the application, even when the guidance follows a standard pattern. Interaction design documents intent. Behavior must be verified in the implementation.

When to use

Use to present a sequence of content in the same space with clear controls.

What to design

Show the current slide, previous and next controls, and indicators when used. If rotation is automatic, show a pause control.

How it behaves

Controls change the slide without unexpectedly moving focus. Automatic rotation pauses when the carousel receives focus.

What to document in Figma

Record rotation, pausing, control names, and how the current slide is communicated. Gestures and arrow navigation may supplement the controls.

How to review

Check whether the purpose and states are clear on small and large screens and with zoom. Verify documented behavior in the implementation, including keyboard and screen reader use where applicable.

Interaction Design

Questions to ask when designing interactive components of type Carousel.

Important:
Depending on the context in which you build your components, there may be further questions, and some listed here may not be necessary. Assess each case individually.

Designing for "no interaction"

  1. Before interacting, can you visually tell that this is a group of related content?
  2. Before interacting, can you identify which item or slide is active?
  3. Before interacting, can you perceive the item count or current position within the sequence?
  4. With automatic rotation, can you tell whether the carousel is playing or paused?
  5. Are next, previous, item selection, and pause controls available without relying solely on gestures or animations?

Designing for mouse use (any pointing device)

  1. Is there visual feedback when hovering over buttons, indicators, and pause controls?
  2. Is there visual feedback when clicking actionable controls?
  3. Does clicking previous or next display the corresponding slide and update the active indicator?
  4. Does clicking an indicator display the slide associated with that control?
  5. With automatic rotation, does hovering over the carousel pause slide changes?

Designing for gesture use

  1. Do controls have enough area for comfortable touch?
  2. When swipinggestures are provided, do they supplement visible controls?
  3. The gesture of swiping update the active slide and its visual indicator?
  4. Can the carousel be operated without relying exclusively on precise or complex movements?

Designing for keyboard use (any non-pointing device)

  1. Is there visual feedback when focusing each actionable control?
  2. Can you navigate between actionable controls using TAB and SHIFT+TAB?
  3. Can you activate buttons and indicators with ENTER and SPACE?
  4. When changing slides, does focus remain in a predictable position?
  5. When focus enters the carousel, is automatic rotation paused?

Designing for screen reader use

  1. When navigating landmarks or regions, can you identify the carousel by a clear accessible name?
  2. When focusing an actionable control, can you hear its name, role, and state?
  3. When focusing indicators, can you identify which slide will be displayed and which is selected?
  4. Is the active slide's position, such as "2 of 5", communicated when helpful for orientation?
  5. Are automatic updates paused or announced in a controlled way to avoid interrupting reading?

Interaction Methods

Possible interaction methods for components of type Carousel.

Important:
Only the main methods are listed here. Custom components require further study.

Mouse interaction (any pointing device)

  • On hover, each actionable control should provide visual feedback confirming that interaction is possible.
  • Clicking next should display the next slide.
  • Clicking previous should display the previous slide.
  • Clicking an indicator should display the corresponding slide.
  • Clicking the pause control should stop automatic rotation.

Keyboard interaction (any non-pointing device)

  • When focused with the keyboard, each actionable control should provide visual feedback with a visible focus indicator.
  • It should be possible to navigate to the next or previous item using the TAB or SHIFT+TAB keys respectively.
  • Control buttons should be activated with the ENTER and SPACE.
  • Arrow keys may be supplementary interactions, provided they are not the only method and do not conflict with expected patterns.
  • On receiving focus, an automatically rotating carousel should pause slide changes.

Keyboard (or gesture) interaction + screen reader

  • On reaching the carousel, you can identify its accessible name and purpose.
  • When focusing previous, next, pause, or indicator controls, their names should describe the action performed.
  • The active slide and its position in the set should be perceptible when needed for orientation.
  • Changing slides should not move focus unexpectedly.
  • On mobile devices, controls must be reachable through screen reader gestures and activatable by double-tap.

Gherkin

BDD (Behavior-Driven Development) methodology focusing on three pillars: User Stories, Acceptance Criteria, and Gherkin Syntax (Given, When, Then).

Scenario: Given that I am on a page containing a carousel

Keyboard navigation

  1. WHEN I use the Tab key to move focus to the carousel controls
  2. The focus I SEE is strongly indicated visually
  3. THEN, when I use the Enter or Space keys to activate a control
  4. I SEE the corresponding slide displayed
  5. AND I SEE the current slide indicator updated
  6. AND focus remains in a predictable position

Automatic rotation

  1. WHEN the carousel has automatic rotation
  2. I SEE a control to pause, stop, or control the animation
  3. THEN, when focus enters the carousel or the mouse hovers over it
  4. I SEE automatic rotation paused
  5. AND, when I activate the pause control, automatic slide changes stop

Screen reader on desktop

  1. When I use a screen reader on a computer (NVDA, JAWS, VoiceOver) and navigate to the carousel, the following happens:
    • I HEAR the accessible name of the carousel or its containing region.
    • I HEAR each control's name, such as previous slide, next slide, pause carousel, or select slide.
    • I HEAR the current slide's state or position when needed for orientation.
  2. THEN, when I activate a carousel control
  3. I HEAR or perceive that the slide updated without repetitive announcements or excessive interruptions.

Screen reader on mobile devices

  1. WHEN I use a screen reader on a phone (TalkBack, VoiceOver) and swipe to navigate the carousel, the following happens:
    • I HEAR the accessible name of the carousel or its containing region.
    • I HEAR controls and indicators in a logical order.
    • I HEAR names that make each control's action clear.
  2. THEN, when I double-tap to activate a control
  3. I HEAR or perceive that the corresponding slide was displayed without losing context.

Considerations

  • If there is automatic rotation, there must be a clear way to pause, stop, or control the animation.
  • The carousel should pause when it receives keyboard focus or the mouse hovers over it.
  • Important content should not exist only in slides that disappear automatically.
  • Animations should respect reduced motion preferences.
  • Visual indicators, such as dots, need accessible names and a perceptible active state.
  • Use carousels thoughtfully, as they add navigation complexity and can hide content.
